# Skill: agent

Loads an agent definition from `registry/agents/` and delegates a task to it as a sub-agent. Activated when the operator (or a calling skill) uses `<slug>:agent` in a task field. Also handles `agent create <slug>` to author new agent definitions.

Two layers, one source of truth:

1. **Definition** at `registry/agents/<slug>.md`: operator-managed, vault-native.
2. **Shim** at `.claude/agents/<slug>.md`: harness-discoverable, generated by `scripts/agent_shim.py`, never hand-edited. If the two disagree, the registry definition wins; the shim is regenerated on every drift.

---

## Triggers

```
<slug>:agent
agent create <slug>
```

Appears inline in the task field of a KERNEL+V prompt. Examples:

- `"Delegate the review of the draft article to demo-critic:agent."`
- `"Task: summariser:agent, condense the attached transcript."`
- `"agent create demo-critic"`

---

## Tools required

`Read`, `Write`, `Edit`, `Bash`, and the sub-agent spawning tool (`Task` in Claude Code).

`Write` and `Edit` are used only during agent creation. Activation uses `Read` and `Bash` (lookup and shim freshness) plus one sub-agent spawn. Shim writes happen only through `scripts/agent_shim.py`, never directly.

---

## MCP awareness

If a ContextOS MCP server is configured for this vault, the creation flow (Step 6) prefers its tools over the harness's raw `Write`/`Edit` for the registry definition and its index row, falling back automatically if MCP is unavailable. Check once per invocation: attempt `mcp__contextos__vault_info`; if it succeeds, prefer the named MCP tools per step below, falling back to `Write`/`Edit` only if a specific call errors. If `vault_info` is unavailable or errors, use `Write`/`Edit` throughout. Shim generation always runs via `scripts/agent_shim.py` regardless — it is bespoke code generation with no MCP equivalent.

## Flow

### Step 1: extract slug

Extract the agent slug from the trigger. Normalise to lowercase-hyphenated form.

Detect the trigger type:

- `<slug>:agent` in a task field → **activation flow** (Steps 2-5).
- `agent create <slug>` as a standalone command → **creation flow** (Step 6).

Run the lookup for either trigger:

```bash
session-start >/dev/null 2>&1
source "${TMPDIR:-/tmp}/plugin-data.env" 2>/dev/null
python $CONTEXT_OS_PLUGIN_ROOT/scripts/registry_lookup.py \
  --vault-root . \
  --type agent \
  --slug "<slug>"
```

### Step 2: activation - agent not found

If `found` is false:

1. Report to the caller:
   > "No agent definition found for `<slug>`. Available agents: [list from `available`, or 'none yet'].
   > Run `agent create <slug>` to define a new one, or continue without delegating."
2. Ask whether to proceed without delegating, use the closest available agent, or create a new one. Do not spawn anything.

### Step 3: activation - validate the delegation

If `found` is true:

1. Read the agent definition at `file`.
2. Collect from the caller: **context** (the situation), **task** (the delegated objective), and **inputs** (files, text, prior outputs).
3. Validate the supplied inputs against the definition's `## Inputs contract`. If any required item is missing, **fail fast** before spawning:
   > "Delegation to `<slug>:agent` is missing required inputs: [each missing item, named
   > as the contract names it]. Supply them and re-delegate."
4. Do not substitute guesses for missing inputs. Do not spawn with a partial contract.

### Step 4: activation - ensure shim freshness

Every invocation checks the shim before spawning:

```bash
session-start >/dev/null 2>&1
source "${TMPDIR:-/tmp}/plugin-data.env" 2>/dev/null
python $CONTEXT_OS_PLUGIN_ROOT/scripts/agent_shim.py --vault-root . --slug "<slug>"
```

The script is idempotent: it writes the shim when missing or stale and reports `fresh` otherwise. A `regenerated` status means the definition drifted since the last run; the registry definition has won, as it always does. If the script reports errors, the definition violates the schema: report the errors and stop.

### Step 5: activation - compose and spawn

Compose a KERNEL+V prompt for the sub-agent:

| Section | Source |
| --- | --- |
| `<context>` | From the caller: the situation the delegation sits in |
| `<tasks>` | The delegated task, framed by the definition's `## Identity` and `## Method` |
| `<inputs>` | From the caller, validated against `## Inputs contract` in Step 3 |
| `<constraints>` | The definition's `## Constraints`, verbatim |
| `<outputs>` | The definition's `## Outputs contract`, verbatim |
| `<verify>` | Derived from `## Outputs contract`: every contracted section present, every constraint respected |

Spawn the sub-agent:

1. Prefer the harness-registered agent type matching the shim (the slug). In Claude Code, the shim in `.claude/agents/` registers it for the Task tool.
2. If the runtime does not list the shim's agent type (Cowork sessions may not), spawn a general-purpose sub-agent with the definition body prepended as its system framing and the definition's `model` requested explicitly (`inherit` means no override). Probed Cowork behaviour confirms sub-agent spawning with model override works; plugin env vars do not, so always pass vault-relative paths, never `$CLAUDE_PLUGIN_ROOT`, inside the composed prompt.
3. Pass the composed KERNEL+V prompt as the sub-agent's task.

Return the sub-agent's output to the caller **in the definition's outputs contract**. If the sub-agent returns output that violates the contract, reshape it into the contracted sections; never silently pass through a malformed result.

### Step 6: creation flow

When the operator requests `agent create <slug>`:

1. Read `memory/operating/vault-conduct.md`.
2. Check whether `registry/agents/<slug>.md` already exists. If so, confirm before overwriting.
3. Interview the operator sequentially (wait for each answer):
   - `"Display name: full display name for this agent? (e.g. 'Demo Critic', 'Summariser')"`
   - `"Description: one line: what this agent does and when to delegate to it."`
   - `"Model: which model should this agent run on? Choose one: sonnet | opus | haiku | inherit."`
   - `"Tools: what may this agent use? Choose one: read-only | read-write | all | an explicit list of tool names."`
   - `"Identity: which role does this agent reason as? (e.g. 'as the engineer:role')"`
   - `"Method: which hats does it wear, in what order, or what numbered method does it follow?"`
   - `"Inputs contract: what must the caller supply for this agent to run? Name each item."`
   - `"Outputs contract: the exact shape the agent returns. Name each required section."`
   - `"Constraints: hard stops and boundaries. What must this agent never do?"`
4. Check whether `templates/registry-agent.md` exists in the vault. If it does, read it and use its content as the template, substituting the interview answers from Step 3 into its placeholders by matching section headings. If the custom template contains a section this skill has no interview answer for, leave its placeholder in place and flag it to the operator in the confirmation message (Step 8) rather than inventing content. If `templates/registry-agent.md` does not exist, use the fallback template below verbatim. Write `registry/agents/<slug>.md` with the resulting content. If MCP is available, prefer `mcp__contextos__note_create` with `frontmatter: {name: "<Title> Agent", description: "<one line>", model: "<model>", tools: "<tools>"}` and `content` set to everything from `# Agent: <Title>` onward; otherwise use the `Write` tool directly.
5. Add a row to `registry/agents/index.md`: `| [<Display Name>](<slug>.md) | <slug> | <one-line description> |` If MCP is available, prefer `mcp__contextos__fs_edit_file` anchored on the table's last existing row; otherwise use the `Edit` tool.
6. Generate the shim. This always runs as a script; shim generation has no MCP equivalent:
   ```bash
   session-start >/dev/null 2>&1
   source "${TMPDIR:-/tmp}/plugin-data.env" 2>/dev/null
   python $CONTEXT_OS_PLUGIN_ROOT/scripts/agent_shim.py --vault-root . --slug "<slug>"
   ```
7. Append to the daily log. If MCP is available, call `mcp__contextos__vault_log_append` with `entry: "agent create | Created agent definition: <slug>"` and `files: ["registry/agents/<slug>.md", ".claude/agents/<slug>.md"]`. Otherwise, append to `memory/log/YYYY/MM/YYYY-MM-DD.md`:
   ```
   HH:MM | agent | agent create | Created agent definition: <slug> | files: registry/agents/<slug>.md, .claude/agents/<slug>.md
   ```
8. Confirm to the operator:
   > "Agent `<slug>` created at `registry/agents/<slug>.md` with shim at
   > `.claude/agents/<slug>.md`. Use `<slug>:agent` in any future task to delegate to it."

## Agent file template (fallback)

Used only when `templates/registry-agent.md` is not present in the vault.

```markdown
---
name: <Title> Agent
description: <one line: what this agent does and when to delegate to it>
model: <sonnet | opus | haiku | inherit>
tools: <read-only | read-write | all | an explicit list of tool names>
---

# Agent: <Title>

## Identity

<Role composition, e.g. "As the engineer:role.">

## Method

<Hat composition or a numbered method.>

## Inputs contract

- <item>: <what the caller must supply>
- <item>: <what the caller must supply>

## Outputs contract

- **<Section name>**: <what belongs here>
- **<Section name>**: <what belongs here>

## Constraints

- <hard stop or boundary>
- <hard stop or boundary>
```

---

## Tools mapping

The definition's `tools` field maps deterministically to the shim's frontmatter:

| Definition declares | Shim `tools:` frontmatter |
| --- | --- |
| `read-only` | `Read, Glob, Grep` |
| `read-write` | `Read, Glob, Grep, Write, Edit` |
| `all` | Key omitted (all tools available) |
| Explicit list | Passed through verbatim |

The definition's `model` field maps directly, except `inherit`, which omits the shim's `model:` key so the sub-agent uses the caller's model.

---

## Invariants

- Activate only on explicit `<slug>:agent` trigger. Never auto-delegate from task keywords.
- The registry definition is the single source of truth. Shims are generated artefacts: never hand-edit `.claude/agents/<slug>.md`; on any disagreement, regenerate from the registry.
- Check shim freshness on every activation, before spawning.
- Never spawn with an incomplete inputs contract. Fail fast and name what is missing.
- Return output only in the definition's outputs contract.
- Never invent agent content. If a slug is not found, report it and ask.
- Creation writes only `registry/agents/<slug>.md`, updates `registry/agents/index.md`, and generates the shim via `scripts/agent_shim.py`. No other files.
